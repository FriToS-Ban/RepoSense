## Decision

**The dense channel is implemented and evaluable, but it has not been measured, and it stays off.**

Measuring it needs one of two things this environment does not have:
- **an embedding API key.** The only one in the repository is in the committed `backend/.env.save`, which the user was told to rotate; using it would be wrong;
- **a local embedding model.** That means installing `torch` or `onnxruntime` plus ≥ 100 MB of weights. Design §7 rules out new heavy dependencies before a measured need.

The evidence so far does not create that need:
- the lexical channel is the strongest single channel on T2 (M4);
- its main loss is *depth* (66% of judged symbols generated at k = 50 per seed vs 97% at k = 1,000), which tuning addresses (M6);
- the largest remaining loss is fusion (M4, M5), which a learned ranker addresses (M9).

Dense retrieval's distinctive strength, bridging natural language and identifiers, applies mainly to the PR-text part of the query. That part is **not** minor. In M6's one-factor runs, dropping the PR text from the lexical query costs .061 R@budget on T2-train, and doubling its weight helps. NL-to-code matching of the PR description is therefore the most plausible place for a dense model to add recall, and the first thing to measure once a key is available.

## What was built

- **`DenseBackend` interface.** `embed(texts, kind)`, where kind is `passage` or `query` (asymmetric models such as NVIDIA's embed-code take `input_type`).
- **`OpenAICompatibleBackend`.** Any `/v1/embeddings` endpoint (NVIDIA NIM, OpenAI, a local server). It is configured **only** from the environment (`DENSE_BASE_URL`, `DENSE_MODEL`, `DENSE_API_KEY`), never from `.env` files, and the evaluation refuses to start without them because it makes paid calls.
- **`EmbeddingCache`.** Vectors keyed by (model, symbol content hash), persisted as JSON lines. A symbol version that appears in hundreds of T2 snapshots is embedded once; production would reuse the M7 vector outbox the same way.
- **`DenseIndex` and the `dense` channel.** One passage per symbol (path, qualified name, signature, docstring, body prefix; 1,500 characters). There is one query per seed (its changed and context lines) plus one for the PR text, merged round-robin, with the same exclusions as the lexical channel. Cosine search is pure Python; brute force is fast enough at these repository sizes.
- **`eval/run_t2_dense.py`.** Runs A, **B** (dense alone) and **AB** (lexical + dense, RRF) on T2, and counts judged symbols that *only* the dense channel generates.

Tests (4, `backend/tests/test_dense.py`): the cache embeds each symbol version once (in memory and reloaded from disk); the channel and its fusion; the channel is inert without a backend; the remote backend requires explicit environment configuration.

## A control that changes the decision rule

The design's rule (§9) keeps dense if "C > A on T2 (p < 0.01) **or** it adds ≥ 5% unique relevant candidates". To test the second clause, the harness was run with the **feature-hashing stand-in**. That backend hashes identifier tokens into 256 signed buckets and knows nothing about meaning.

| T2 (300 queries, `sym_all`) | R@budget | R@10 | nDCG@10 |
|---|---|---|---|
| A (lexical) | .617 | .468 | .356 |
| B-hashing (stand-in alone) | .399 | .229 | .160 |
| AB-hashing (A + stand-in, RRF) | .577 | .390 | .297 |

- AB-hashing − A: R@budget **−.040** (p_holm .032), R@10 −.078 (p_holm 9e-4).
- The stand-in generates 710 of the 1,122 judged symbols, and **72 (6.4%) that no lexical, structural, PPR or co-change candidate list contains**.

**The 5% clause is not evidence of semantic value.** A channel with no semantics clears it, because *any* differently-behaving retriever generates some judged symbols the others miss: different tokenisation, no IDF, and the PR text treated as a separate query. The bar has to be relative to this control. The rule is therefore amended (ADR-10 note): a dense model is kept only if
1. AB beats A on T2 R@budget with p < 0.01, **and**
2. its unique relevant candidates exceed the hashing control's by a margin whose bootstrap CI excludes zero.

## How to run it when a key is available

```
DENSE_BASE_URL=https://integrate.api.nvidia.com/v1 DENSE_MODEL=nvidia/nv-embedcode-7b-v1 DENSE_API_KEY=… python -m eval.run_t2_dense
python -m eval.compare eval/results/t2-dense-<model>:AB eval/results/t2-dense-<model>:A --view sym_all
```

The 300 T2 snapshots contain 10,087 distinct symbol versions; each is embedded once and cached, plus about 1,300 queries. Ask before running it: it is the first step in this roadmap that spends money.
