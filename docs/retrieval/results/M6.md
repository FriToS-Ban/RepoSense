## What was built

- **T2-train.** The 100 qualifying commits per repository that precede T2-test's 50: 600 queries, all older than every test query (`python -m eval.benchmarks.t2 --train`; a test asserts the temporal separation). Tuning and, in M9, learning-to-rank use only this split.
- **Query-time BM25F parameters.** The index stores raw per-field term frequencies, so field weights, k1 and b are search arguments. A test checks that they equal re-indexing. One index per snapshot therefore serves every configuration.
- **Query weighting:**
  - `context_weight`: weight of the hunk's unchanged lines inside a seed;
  - `pr_text_weight`: weight of the commit message or PR description;
  - `residual_weight`: boosts query terms that occur in the seed's *unresolved* reference chains, i.e. the identifiers the graph could not bind (design §5.3);
  - PRF (`prf_docs`, `prf_terms`, `prf_weight`): expands the query with frequent name and signature terms of the top hits, an RM3-like ablation.

## Protocol

- **Deviation from the design, and why.** The design said "tune on T1-dev, validate on T2". M4 and M5 showed that T1 and T2 disagree, and T1 is circular. So the lexical channel is tuned on **T2-train**, which is non-circular and temporally earlier, and validated once on **T2-test**. T1 and T3 are reported as regression checks.
- **Grid.** One pass over T2-train answers every query with 63 configurations:
  - the M2 defaults;
  - one-factor variations (each field weight zeroed and doubled; k1, b; query weights; candidate depth; residual boost; PRF);
  - 32 seeded random joint configurations.
- **Selection.** The highest mean R@budget on T2-train, with nDCG@10 as the tie-break.

## Per-factor contributions (T2-train, 600 queries; Δ R@budget vs the defaults, .633)

| Factor | Δ | Factor | Δ |
|---|---|---|---|
| body field off | **−.161** | PR text off | **−.061** |
| qual+path field off | −.011 | PR text × 2 | +.008 |
| name field off | +.003 | context lines off | −.003 |
| signature field off | +.006 | context lines weight 1.0 (= changed lines) | −.023 |
| docstring field off | **+.014** | residual boost × 2 | +.007 |
| body × 2 | −.010 | PRF, 5 docs | +.002 (nDCG@10 −.017) |
| docstring × 2 | −.012 | PRF, 10 docs, weight .5 | −.022 |
| b = .3 | −.021 | max candidates 25 / 60 | −.024 / +.005 |
| k1 = .6 / 2.0 | −.010 / −.001 | score floor .3 | −.034 |

Reading:
- **The body carries the channel.** Identifiers used *inside* a symbol are what links co-changed code; names alone are weak, and the name field's default weight of 3 is too high.
- **The PR text matters**: −.061 without it. That supports the PR-description query path, and it is where a dense model (M8) would most plausibly help.
- **Docstrings slightly hurt.** Natural-language overlap with the commit message finds documented but unrelated symbols.
- **PRF does not help**, matching the design's choice to keep it an ablation.

## Selected configuration ("rand20") and its validation

`name 1.0, qual 1.5, sig 3.0, doc 0.5, body 1.0; k1 0.8, b 0.75; PR text 2.0; context 0.5; 50 per seed, score floor .15; 60 candidates; residual boost 2.0`. T2-train: R@budget .662 (+.029).

| Benchmark (paired, Holm within the comparison) | A_tuned − A |
|---|---|
| **T2-test** `sym_all` R@budget | **+.025** [+.003, +.048], p .032, p_holm .063 |
| **T2-test** `sym_all` nDCG@10 | **+.026** [+.009, +.043], p_holm .017 |
| T2-test `sym_all` R@10 / MRR | +.035 (p_holm .051) / +.026 (p_holm .063) |
| T2-test `sym_tests` R@10 | +.048, p_holm .009 |
| T2-test `sym_code` R@budget | +.018 (n.s.) |
| T1 deps R@budget (callees by name) | **−.045**, p_holm .009 |
| T1 impact R@budget | −.013 (n.s.) |
| T3 context sufficiency | .974 vs .961 (n.s.) |

- **The train gain transferred.** +.029 on train vs +.025 on test, so the best-of-63 selection did not overfit noticeably. The R@budget gain is small and borderline after correction; the early-ranking gain survives it.
- **T1 disagrees again.** The tuned configuration lowers the name weight (3 → 1). T1's deps ground truth is "callees referenced in the rewritten function", found by name, so T1 loses. T3, which needs exactly those callees for bugs, shows no loss. The graph channel serves callee lookup anyway (M3).

**Decision.** `TUNED_LEXICAL` becomes the lexical configuration of production v2 (`context_v2`) and of the M9 reranker's features. `RetrievalConfig`'s own defaults stay at the M2 values, so M2–M5 results remain reproducible. System `A_tuned` is gated in CI on T1 and T2.

## Exit criteria (design §9)

| Criterion | Status |
|---|---|
| Tuned on a development split, validated on T2 | ✅ T2-train → T2-test (T1-dev replaced by T2-train; see protocol) |
| Per-field contribution reported | ✅ table above |
| PRF ablation | ✅ no benefit |
