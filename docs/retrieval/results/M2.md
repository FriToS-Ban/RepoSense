## What was built

- **`diff.py`:** a unified-diff parser. It handles added, deleted, renamed and binary files, `\ No newline`, and stripped empty context lines. v1 turned every file header into a query and capped retrieval at 8 chunks; neither happens any more.
- **`seeds.py`:** links each changed line to its innermost enclosing symbol. New-side lines map through the head version extracted on the fly; removed lines map through the base snapshot. Each seed gets a change type (`body_changed`, `signature_changed`, `added`, `removed`, `test_changed`, `module`) and the relation plan of design §5.2. A seed also records whether the change is structural at the AST level, which decides whether M3 needs an overlay graph.
- **`lexical.py`:** BM25F over symbol fields, following Robertson, Zaragoza & Taylor (2004):

  | Field | Weight |
  |---|---|
  | name | 3.0 |
  | qualname + path | 1.5 |
  | signature | 2.0 |
  | docstring | 1.0 |
  | body | 1.0 |

  Query = the seed's changed lines (weight 1) plus its context lines (0.5). **Seeds and every symbol of a changed file are excluded** (design P4). Multiple seeds are merged round-robin.
- **`packing.py`:** budget-aware, relation-aware context construction:
  - seeds first, together capped at 40% of the budget
  - candidates in rank order at their cheapest useful rendering: a **call-site window** for callers of a seed (found through graph evidence lines), compact signature and docstring otherwise
  - remaining budget upgrades candidates to full source in rank order
  - a class shown in full covers its methods
  - every item gets a provenance label
- **`pipeline.py`:** `RepoRetriever(graph).build_context(diff, head_content, pr_text)` returns the context text, the items, and a JSON trace: seeds, plan, candidates with scores, renderings, dropped items with reasons, timings.

Tests: 8 in `backend/tests/test_retrieval.py`, covering the diff parser, seed linking (body, signature, added and removed symbols), BM25F field weighting, exclusion and determinism, packing (call sites for callers, budget bound, containment) and the end-to-end pipeline. 28 backend tests pass in total.

## Results on T1 (cross-file ground truth, 224 deps + 113 impact queries)

| System | deps R@10 | deps R@budget [95% CI] | deps MRR | impact R@10 | impact R@budget [95% CI] | impact MRR |
|---|---|---|---|---|---|---|
| S2 v1 pipeline + BM25 | .015 | .049 [.027, .073] | .010 | .083 | .201 [.137, .270] | .032 |
| S1 v1 pipeline + **oracle** | .164 | .388 [.330, .450] | .054 | .244 | .598 [.510, .683] | .080 |
| S3 BM25 raw, top-50 list (no budget) | .259 | .620 [.564, .677] | .103 | .614 | .862 [.805, .915] | .204 |
| **A: BM25F + v2 packing** | **.410** | **.599** [.541, .656] | **.181** | **.747** | **.899** [.844, .946] | **.350** |

Paired randomization tests (`eval.compare`, 10⁴ permutations, Holm-adjusted):
- **A vs S2:** deps R@budget **+.550** [+.488, +.610], impact **+.698** [+.619, +.772], both p_holm = 8e-4, the floor of the test's resolution.
- **A vs S1:** with a *lexical* first stage, A beats the v1 pipeline even when v1 is given perfect candidates: deps +.21, impact +.30 (p_holm 8e-4). This confirms the design's central claim: v1's loss was in representation and packing, not in the retriever.
- **A vs S3:** A's 12k-character context reaches the recall of BM25's unbudgeted top-50 list (deps −.021, p = .30; impact +.037, p = .08) while ranking far better: R@10 +.15 / +.13, MRR +.08 / +.15 (p_holm ≤ .002).
- **Exit criterion** ("A beats S2 on T1 Recall@budget, p < .01"): **met**.

Impact queries: every judged caller that reached the context was shown with its call site (R@budget with appropriate renderings = R@budget = .899).

Latency per review (local CPU, no network): p50 26 ms / p95 67 ms (deps), p50 14 ms / p95 38 ms (impact). Of that, 11–23 ms is extracting the head version of the changed file. Building the per-snapshot index takes 0.07–0.46 s.

### Where System A still loses (failure taxonomy, cross-file ground truth)

| Stage | deps | impact |
|---|---|---|
| in context | 262 (55%) | 245 (87%) |
| generated, then packed out (budget) | 26 (5%) | 11 (4%) |
| **never generated by the lexical channel** | **192 (40%)** | 27 (10%) |

Candidate generation, not packing, is now the bottleneck for dependencies. Two more measurements point the same way:
- 2-hop dependencies are barely found (R@budget .148).
- `sym_all` recall (.471) is lower than cross-file recall (.599), because changed-file symbols are excluded from lexical candidates and same-file callees are therefore never offered.

Both are what M3's structural channel is for: typed expansion from seeds, including same-file callees, plus 2-hop. That has to be judged against the caveat that T1 rewards structure by construction (design §6.2).

## Notes

- **Context composition (deps):** about 31 items per review: 1 seed (10% of the characters), ~3.6 full bodies, ~26 compact signatures, ~0.2 call sites. Compact renderings are what lets recall scale within the budget (spike D).
- **Not yet wired into the review endpoint.** `get_relevant_context` still serves the hot-fixed v1. Serving v2 in production needs v2 indexing on enable and push plus the head file contents at review time. Those arrive with the tarball-based acquisition in M7, behind `RETRIEVAL_ENGINE=v2` (design §8).
- The CI gate now also re-runs System A and fails on any metric change (`eval/gate.py`).
