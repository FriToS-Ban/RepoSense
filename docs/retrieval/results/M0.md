## What changed

1. **`eval/` package.** This is the Phase 1 scratch harness rebuilt as a tested, deterministic package; see [`eval/README.md`](../../../eval/README.md). It contains:
   - pinned, fingerprinted corpora
   - a frozen reference resolver
   - the T1 generator and frozen T1 data (`eval/data/t1/`)
   - baseline BM25
   - metrics and statistics (bootstrap CI, paired randomization test, Holm)
   - a v1 replay executed from git at `887d2fd`
   - a runner writing JSON results and TREC run files
   - `eval.compare` for paired system comparisons
2. **v1 hotfix** in [`backend/services/rag.py`](../../../backend/services/rag.py): `all_matched_nodes` is now initialized before use (two lines moved). Since `7ce9e6d` (2026-05-27), every review had received an empty RAG context (audit finding W1).
3. **Regression tests** in [`backend/tests/test_rag_regression.py`](../../../backend/tests/test_rag_regression.py):
   - the context contains the changed file's nodes and the retrieved nodes, with no swallowed error
   - the hotfixed function produces *exactly* the output of the fix measured in the audit
   - against the pre-hotfix `rag.py`, all three tests fail, so they would have caught W1
4. **Unit tests** (22) for metrics (hand-computed cases), statistics, tokenizer/BM25, and the reference resolver. The resolver tests use a fixture covering star imports, relative imports, re-export chains, `super()`, MRO lookup through `self`, alias imports, and local shadowing. Further tests cover T1 views and determinism, and v1 replay behaviour (header pseudo-hunks, swallowed error).

### Why S1 (the oracle bound) moved from .404 to .388

The audit's oracle returned the ground-truth nodes in Python **set iteration order**, which depends on `PYTHONHASHSEED`. Ties between colliding nodes were broken by random UUIDs. Rerunning the unchanged audit harness under two other hash seeds showed:
- S0, S2, S3, S4 are bit-identical across runs
- S1 varies by up to 0.010 (deps cross-file R@all: .404 / .396 / .403)

M0 fixes the oracle order (cross-file first, then lexicographic) and seeds the node IDs. The deterministic value is:

| S1, cross-file | Audit (hash-dependent) | M0 (deterministic) |
|---|---|---|
| deps R@all | .404 [.345, .467] | **.388 [.330, .450]** |
| deps R@20 | .355 | .344 |
| impact R@all | .597 | .598 |

The conclusion is unchanged: even with a perfect first stage, the v1 pipeline delivers about 40% of cross-file dependencies and about 60% of cross-file callers. The audit document carries a pointer to this note.

### Diagnostics redefined

- **SQL statements per review** are now measured with a fresh DB session per simulated review, as in `review.process_pr_review`. The audit's long-lived session made the count depend on run history. New values: deps S2 23.1 (audit 22.3), impact S2 23.4 (22.1).

## Notes and limitations

- The local virtualenv in `backend/venv` predates `requirements.txt` (it lacks `pinecone`, `openai`, `google-genai`, `psycopg2-binary`). The evaluation and tests do not need them because the fakes stand in. Running the app itself still needs a fresh install.
- The hotfix changes production behaviour: reviews of repositories with a knowledge graph now send up to 12,000 extra characters of context to the LLM.
- T1 remains structurally biased (design §6.2). The first non-circular benchmark is T2 (M4).
